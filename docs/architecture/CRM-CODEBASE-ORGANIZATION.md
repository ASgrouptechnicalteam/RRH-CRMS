## 3. Layering (import-direction rules)

Strict direction; violations create cycles:

```
routes → services → policies → authz ;  services → workflows ;  services → utils
middleware applied at the route layer
```

- **routes** are thin: authenticate → authorize → delegate to a service → respond.
- **services** hold domain logic + transactions (own a `PrismaClient` each).
- **policies** (`*.policy.ts`) do object-level checks; consumed by
  `authz/authorization.ts` and by services. All 15 imported (verified):
  property/lead/siteVisit/expenseRefund/task/project/document/kyc via
  `authorization.ts`; booking/customer/installment/opportunity/payment via services.
- **workflows/** = state machines (`workflowEngine.ts` + per-domain `*..workflow.ts`
  + `types.ts`); `WorkflowDomain`/`WorkflowEngine` consumed by every domain service.
- **middleware/** applied at routes (auth, authz, rate-limit, correlation-id, validate).
- **services/ai/** (Phase 17-A) is a self-contained leaf.

### 3.1 The AI exception (important)
`apps/api/src/services/ai/application.ts` is imported **only by the test**
`tests/api/phase17a-ai-foundation.test.ts` and is **not** mounted in `server.ts`.
This is the **intended** Phase 17-A state: AI is an interpretation layer tested
in isolation — no AI HTTP endpoint exists (`server.ts` mounts no AI router;
OpenAI/OpenRouter SDKs are declared in `package.json` but unused in code).
**Keep, do not delete.**

## 4. Path aliases & build

| Alias / import            | Resolution                                  | Used by |
|---------------------------|---------------------------------------------|---------|
| `@rrh-ems/shared`         | workspace link → `packages/shared/src/index.ts` | all    |
| `@/...`                   | `apps/api/src/...`                          | tests (jest `moduleNameMapper`) |
| relative `../`            | all production source                       | all     |

- Root `tsconfig.json`: project references to `apps/api` + `apps/web`; **no**
  `paths` mapping (aliases resolved at test-time by Jest, at build-time by Vite).
- `jest.config.js`: `preset: 'ts-jest'`, `testEnvironment: 'node'`,
  `roots: ['<rootDir>/tests/api']`, `setupFilesAfterEnv: ['<rootDir>/tests/api/setup.ts']`.
