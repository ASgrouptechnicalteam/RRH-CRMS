# **8\. The EXTRA CHARGES system**

This is the part I recommend you make **dynamic**, rather than creating 30 permanent database columns.

For example, don't only create:

eastFacingCharge  
cornerCharge  
parkFacingCharge  
roadFacingCharge

Instead create an **Additional Charges** system.

### **Example**

Property:

**Plot P-105**

| Charge        | Type     | Amount      |
| ------------- | -------- | ----------- |
| Base Price    | Base     | ₹50,00,000  |
| East Facing   | Premium  | ₹2,00,000   |
| Corner        | Premium  | ₹3,00,000   |
| Park Facing   | Premium  | ₹1,50,000   |
| 40-ft Road    | Premium  | ₹1,00,000   |
| Development   | Charge   | ₹75,000     |
| Documentation | Charge   | ₹25,000     |
| Discount      | Discount | \-₹1,00,000 |

### **Calculation**

Base Price ₹50,00,000  
\+ East Facing Premium ₹2,00,000  
\+ Corner Premium ₹3,00,000  
\+ Park Facing Premium ₹1,50,000  
\+ Road Premium ₹1,00,000  
\+ Development Charge ₹75,000  
\+ Documentation Charge ₹25,000  
\- Discount ₹1,00,000  
\-----------------------------------------  
Final Property Price ₹57,50,000

This is much better because the developer can create new charges later.

For example:

East Facing  
₹2,00,000

North-East Facing  
₹3,50,000

Corner  
₹3,00,000

Park Facing  
₹1,50,000

Main Road  
₹2,50,000

Extra Road Width  
₹1,00,000

Premium Location  
₹5,00,000

Higher Floor  
₹500 / Sq.Ft.

Pool View  
₹2,00,000

The source already establishes **Premium Charges** and **PLC (Preferential Location Charges)** as pricing concepts.

# **9\. Best database design for this**

I recommend these main tables:

projects  
│  
└── properties  
│  
├── plot\_details  
├── apartment\_details  
├── villa\_details  
├── house\_details  
├── commercial\_shop\_details  
├── commercial\_office\_details  
└── farm\_land\_details

And independently:

properties  
│  
├── property\_prices  
│  
├── property\_charges  
│  
├── property\_documents  
│  
├── property\_media  
│  
├── property\_status\_history  
│  
└── property\_bookings

### **`property_charges`**

This could contain:

id  
propertyId  
chargeType  
chargeName  
calculationType  
amount  
percentage  
rate  
quantity  
isMandatory  
description  
createdAt  
updatedAt

Where `calculationType` could be:

FIXED  
PER\_SQFT  
PER\_SQ\_YARD  
PERCENTAGE  
PER\_UNIT

That allows you to handle all of these:

East Facing → Fixed ₹2,00,000  
Corner → Fixed ₹3,00,000  
Park Facing → Fixed ₹1,50,000  
Higher Floor → ₹500/Sq.Ft.  
Development → ₹100/Sq.Ft.  
Registration → Percentage  
Parking → Per Slot  
Clubhouse → Fixed

This gives you a **much more scalable property inventory system**.

And importantly, the same project can have:

1000 Plots  
200 Villas  
500 Flats  
50 Houses  
30 Shops  
20 Offices

with every individual property having its **own size, facing, premiums, charges, price, availability and specifications**, while the common project information remains at the Project level.
