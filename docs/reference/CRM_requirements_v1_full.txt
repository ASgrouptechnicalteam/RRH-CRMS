4. CRM → Website Requirements 
4.1 Live inventory eligibility 
●​
The website API must return only properties that the current brand is authorized to publish. 
●​
The property must have completed the CRM approval/publication requirements for that brand. 
●​
The property must be currently Available to appear as live purchasable inventory. 
●​
Reserved properties must not be returned as live inventory. 
●​
Sold properties must not be returned as live inventory. 
●​
Draft, rejected, review-only or otherwise unpublished records must not be exposed. 
●​
Brand scoping must be enforced server-side, not only by frontend filtering. 
●​
Seller identity and internal source type must not be part of public website payloads.

9. Price Requirements 
●​
All listed real-estate prices are negotiable; customer-facing UI should not falsely imply fixed transaction rates. 
●​
Property/project price may be represented as a range such as ₹45L – ₹53L. 
●​
CRM should expose structured numeric price boundaries in INR to allow search and ranking. 
●​
Minimum/maximum search budget is a customer requirement, not a promise of final transaction price. 
Examples:​
  max budget ₹50L → max = 5,000,000​
  ₹40L–₹60L → min = 4,000,000; max = 6,000,000​
  above ₹1Cr → min = 10,000,000​

12.3 Example behavior 
If a customer searches for a 2BHK, an agricultural plot should not receive a poor BHK score; BHK is not applicable and 
the property is outside the intended property-type candidate set. If a residential apartment has BHK missing, that is 
unknown and should be handled differently from a verified non-match. 
If a customer sets a maximum budget of ₹50L, exact/below-budget properties rank first. Slightly-above-budget 
properties may be shown as related alternatives, clearly labeled as above budget, but must not silently replace exact 
matches.

26. CRM Integration Acceptance Checklist 
1.​ RRH website can retrieve only RRH-approved, published and Available inventory. 
2.​ Sonthillu website can retrieve only Sonthillu-approved, published and Available inventory. 
3.​ CRM can independently publish a shared property to either or both brands. 
4.​ Reserved and Sold inventory cannot be exposed as live purchasable listings. 
5.​ Public payload excludes seller identity and internal source type. 
6.​ Exact coordinates are protected. 
7.​ RERA public indicator is controlled by approved CRM data. 
8.​ Price ranges are available in structured form. 
9.​ New/Resale classification is available. 
10.​ Applicable property-specific attributes are available. 
11.​ Project and inventory relationships are available. 
12.​ Normal Search can be built entirely from canonical CRM data. 
13.​ AI Search can map normalized requirements onto canonical CRM data. 
14.​ Recommendations can use brand-scoped live inventory. 
15.​ Enquiry and Request-a-Call can be created in CRM. 
16.​ Multi-property enquiry can reference multiple selected property IDs. 
17.​ Seller submissions reach CRM without direct publication. 
18.​ Project Manager verification remains a CRM workflow. 
19.​ Digital Marketing review remains a CRM workflow. 
20.​ MD approval remains a CRM workflow. 
21.​ Publication/availability changes propagate to websites. 
22.​ RRH/Sonthillu customer accounts remain separate. 
23.​ Cross-brand data leakage is prevented. 
27. Final Principle 
RRH-CRMS is the business and property authority. The websites should ask CRM for approved public information and 
send customer actions back to CRM. They should not recreate the internal property lifecycle, seller verification, 
project-manager work, Digital Marketing review or MD approval in the websites. 
For the websites to deliver Normal Search, AI Search, dynamic matching, recommendations, property details, project 
pages, shortlist/compare, enquiries and seller submission, CRM needs canonical, brand-scoped, structured and 
sufficiently complete property/project data. 
Where the discussion did not establish an exact field or implementation, this document deliberately marks it for 
repository verification. The next technical step is to inspect the existing RRH-CRMS property schema, lifecycle and APIs 
and reconcile them against this requirement set.
